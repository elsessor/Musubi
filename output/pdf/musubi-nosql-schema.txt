Schema notes

1. ? marks an optional or variant field. Native Firestore Timestamp values are labeled timestamp.
2. Document IDs are part of document paths, not required _id fields.
3. All roles use users. Tasks are embedded maps in events.tasks.
4. Onboarding organization applications use organization_join_requests; requestedByUID identifies the applicant.
5. Join-request status: pending, accepted, rejected. Acceptance updates the applicant's organization membership.
6. Admin accountStatus is derived for API responses: Active, Pending Join Request, Onboarding, Inactive. It is not a required stored user field.
7. Legacy inactive account flags remain supported; pending status is derived from real pending join-request documents.
8. organizations.eventCustomStatuses and events.eventCustomStatuses are optional arrays. Event responses derive their event colors from organization settings.
9. Task attachments, dueDateHistory, nudges, performanceReview and priorityChangeRequest are optional. The two review/request maps may also be null.
10. The supplied live event confirms needsRating, ratedAt, ratedBy, rating and ratingFeedback as additional task fields.
11. Task schedules use strings. Completion, upload, review and rating times use ISO date/time strings.
12. Files use contentType and size; links use url. Link metadata stays in tasks; files also create taskFiles and ordered chunks.
13. Files: maximum 5 MiB; chunks: maximum 512 KiB; attachments per task: maximum 50. Chunk IDs: 0000, 0001, ... .
14. Announcement subcollection documents mirror top-level announcements.
15. Organization members and committees subcollections are legacy; only fields read by current code are listed.
16. Schema combines current code with the supplied event; unseen historical fields may exist. This is schema documentation, not a live database export.
